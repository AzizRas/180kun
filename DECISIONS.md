## Технические решения этого репозитория

| № | Решение | Почему |
|---|---|---|
| Т-01 | Модульный монолит, не микросервисы | Микросервисы не живут на shared-хостинге за $2–3 и не тянутся одним разработчиком. Границы модулей дают то же свойство «убрал — не сломалось» |
| Т-02 | Ни одной внешней зависимости, своя автозагрузка | Заливка папки на любой хостинг без SSH и Composer |
| Т-03 | У каждого контракта есть заглушка | Техническая гарантия, что выключенный модуль не роняет систему |
| Т-04 | Миграции принадлежат модулям | Модуль вырезается вместе со своими таблицами, не задевая чужие |
| Т-05 | Домен возвращает `Result`, не `Response` | Один и тот же код работает из веба, Telegram-бота, CLI и тестов |
| Т-06 | В базе только хеш токена сессии | Утечка дампа не даёт войти под чужим аккаунтом |
| Т-07 | SQLite в режиме WAL, база вне публичной папки | Одновременное чтение при записи; базу нельзя скачать из браузера |
| Т-08 | Модули не делают JOIN через границу | Условие, при котором модуль можно вынести в сервис без переписывания |
| Т-09 | Наружу отдаётся белый список: `assets/` и `index.php` | Первый деплой на Railway показал, что `.htaccess` там не действует и наружу видна вся папка. Белый список не зависит от того, что ещё положат в проект |
| Т-10 | Постоянные данные — в `DATA_DIR`, на Railway — в томе (`RAILWAY_VOLUME_MOUNT_PATH`) | Файловая система контейнера стирается при деплое |
| Т-11 | Миграции применяются сами при первом запросе после деплоя | На Railway и на shared-хостинге нет шага «запусти команду после выкладки» |
| Т-12 | Данные браслета — ручной ввод и импорт CSV, без прямых интеграций | Google Fit REST закрыт для новых приложений и отключается в конце 2026; Health Connect живёт только на Android-устройстве; Google Health API требует проверки приложения — задача сезона 2 |
| Т-13 | Состояние (помеха / перегруз / потеря смысла / отказ) и флаги нагрузки считает код, модель только формулирует | От состояния зависит нагрузка, а её по Р-11 решает только детерминированный код |
| Т-14 | Кризисные темы — отдельный модуль Safety, не часть тренера | Безопасность не должна выключаться вместе с ИИ |
| Т-15 | Доступ к сезону — контракт `Access`, заглушка открывает всё | Выключенный модуль оплаты не должен блокировать продукт |
| Т-16 | Метрики: свой журнал фактов + `analytics.collect` у владельцев данных | Модуль метрик не читает чужие таблицы, а владельцы не знают про панель |
| Т-17 | Выгрузка и удаление через `UserData::register` в каждом модуле | Ядро не знает, где лежат данные; модуль не может тронуть чужую таблицу |
| Т-18 | При удалении аккаунта платежи и журнал фактов обезличиваются, а не стираются | Платёж — бухгалтерский документ; агрегаты сезона остаются по оферте (§ 11) |
| Т-19 | Фото принимает только модуль Media и только при `DATA_RESIDENCY=UZ`; на Railway, Render, Fly, Heroku, Vercel — отказ, даже с флагом | Закон «О персональных данных» (ред. 2026): биометрия — только внутри страны. Код не может узнать страну дата-центра, поэтому владелец заявляет её явно, а известные зарубежные платформы исключены жёстко |
| Т-20 | Исходник фото не хранится: пересжатие GD в JPEG (1600 и 480 точек), поворот по EXIF своим разбором, метаданные пропадают | Координаты GPS и модель телефона не должны попасть ни к кому. GD есть в любой сборке PHP; ImageMagick не нужен, а непроверенный код в пути загрузки хуже его отсутствия |
| Т-21 | Фото отдаются по подписанной ссылке «зритель + размер + срок», срок 10–15 минут, имя файла — 128 бит случайности | `<img>` не умеет слать заголовок сессии; подпись привязывает ссылку к зрителю, срок ограничивает утечку |
| Т-22 | Кто может смотреть, решает владелец смысла (Feed через контракт `Team`), а не хранилище | Media не знает про сквады; модератор видит фото только тех постов, на которые пожаловались |
| Т-23 | В ленте одна реакция «поддержал», имена видит только автор, порядок — по времени | Р-16 и § 11: никаких лайков-счётчиков и сравнения внешности |
| Т-24 | Жалоба «тело» или «чужое лицо» скрывает фото сразу; остальные — после второй | Запрещённое фото не должно висеть до реакции модератора |
| Т-25 | Созвон назначает лидер; где звонок — контракт `CallProvider`: видеочат группы Telegram, по желанию своя комната Jitsi | Бот не умеет начать видеочат сам (нет в Bot API); своя комната — заменой реализации, без переделки расписания |
| Т-26 | Такт планировщика — событие `system.tick`: cron (`tools/tick.php`) или `/api/tick?key=` | Напоминания, сроки фото и пересчёт сквадов не должны зависеть от того, открыл ли кто-то приложение |
| Т-27 | Настройки без переменных окружения — `config.local.php` (те же имена) | На своём сервере один файл читают и сайт, и cron; на хостинге с панелью переменных окружения нет вовсе |
| Т-28 | Интерфейс 2026: светлая/тёмная тема из Telegram, бенто-главная, нижняя панель с кнопкой чек-ина, системные шрифты | Ориентиры — самые сохраняемые health-концепты Pinterest; чек-ин — главное действие дня и должен быть в одном касании |
